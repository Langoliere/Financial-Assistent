# MVP План: Сервис прогнозирования направления цены на следующий торговый день

## Выбранная модель

**LSTM для бинарной классификации**

**Почему:**
- Временные ряды финансовых данных имеют сложные временные зависимости
- LSTM способна улавливать паттерны в последовательности из 20 торговых дней
- В исследовательском ноутбуке LSTM показала потенциал для задачи классификации направления
- LSTM robust к шуму по сравнению с простыми моделями
- Возможность масштабирования до более сложных архитектур в будущем

**Альтернативы (не выбраны):**
- Линейная регрессия - слишком простая для нелинейных паттернов в финансовых данных
- Традиционные модели (XGBoost, Random Forest) - требуют ручного создания последовательных признаков
- Transformers - избыточная сложность для MVP

## Целевая переменная

**Бинарная классификация направления движения цены:**

```
target[t] = 1 если close[t + 1] > close[t]
target[t] = 0 если close[t + 1] <= close[t]
```

**Почему:**
- Прямо отвечает на бизнес-вопрос: "покупать или продавать?"
- Устойчива к нестационарности абсолютных цен
- Легко интерпретировать как торговый сигнал
- Хорошо подходит для оценки бизнес-метрик (accuracy, precision, recall, F1)

## Список признаков

### Рыночные признаки (6)
- open, high, low, close, value, volume

### Календарные признаки (10)
- year, month, day, dayofweek
- is_monday, is_friday, is_last_weekday
- days_to_weekend, days_to_month_end
- quarter

### Динамические признаки (9)
- ret_1, ret_5, ret_20 (доходности за 1, 5, 20 дней)
- ma_5, ma_20 (скользящие средние)
- std_5, std_20 (скользящие стандартные отклонения)
- range = (high - low) / close
- body = (close - open) / open
- volume_change = volume.pct_change(1)

### Технические индикаторы (8)
- rsi_14 (RSI с периодом 14)
- ema_12, ema_26 (экспоненциальные скользящие средние)
- macd = ema_12 - ema_26
- macd_signal (сигнальная линия MACD)
- bb_high, bb_mid, bb_low (полосы Боллинджера)

**Всего: 33 признака**

## Исключенные признаки

### Причины исключения:

1. **target_close, target_return, target_direction** - целевые переменные, не могут быть признаками

2. **returns_1 из ноутбука** - использовался только для EDA, дублирует ret_1

3. **Будущие значения** - любые признаки, использующие shift(-1) или информацию с дат > t

4. **Скалеры, обученные на всех данных** - утечка из будущего при использовании test статистик

5. **Агрегированные признаки по всему периоду** - глобальные минимумы/максимумы, средние по всей выборке

6. **Внешние факторы** - новости, макроэкономические индикаторы (нет в текущем датасете)

### Причины невозможности инференса:
- Признаки, требующие доступ к данным следующих торговых дней
- Признаки, вычисленные на основе тестовой выборки при обучении

## Train/Validation/Test Split

**Хронологическое разделение без перемешивания:**

- **Train (80%)**: первые 2048 наблюдений
- **Validation (10%)**: следующие 256 наблюдений
- **Test (10%)**: последние 256 наблюдений

**Почему:**
- Для временных рядов критически важен хронологический порядок
- Тестовая выборка имитирует реальный сценарий прогнозирования в будущем
- Позволяет оценить стабильность модели на отложенном периоде
- Соответствует исследовательскому ноутбуку

**Примечание:**
- Для LSTM последовательностей используется контекст из предыдущих сегментов
- Валидационная последовательность получает 20 дней контекста из train
- Тестовая последовательность получает 20 дней контекста из train + val

## Структура Feature Pipeline

```
1. Data Loading
   ├─ Загрузка OHLCV свечей с MOEX через apimoex
   ├─ Проверка качества данных (пропуски, дубликаты, сортировка)
   └─ Преобразование datetime индекса

2. Feature Engineering
   ├─ Календарные признаки (из datetime индекса)
   ├─ Динамические признаки (rolling statistics, returns)
   ├─ Технические индикаторы (RSI, MACD, Bollinger Bands)
   └─ Удаление строк с NaN после инженерии признаков

3. Target Creation
   ├─ target_direction = (close.shift(-1) > close).astype(int)
   └─ Удаление последней строки (без цели)

4. Chronological Split
   ├─ Разделение на train/val/test по времени
   └─ Сохранение индексов для обратного сопоставления

5. Scaling
   ├─ MinMaxScaler для признаков (fit на train, transform на val/test)
   ├─ Минимизация искажений временных зависимостей
   └─ Сохранение scalers для инференса

6. Sequence Generation (для LSTM)
   ├─ Окно lookback = 20 торговых дней
   ├─ Формирование 3D тензоров (samples, timesteps, features)
   └─ Добавление контекста для val/test из предыдущих сегментов

7. Feature Schema
   ├─ Сохранение порядка признаков в feature_schema.json
   └─ Сохранение типов признаков для валидации на инференсе
```

## API Endpoints

### 1. GET /health
**Назначение:** Health check для мониторинга и load balancer

**Response:**
```json
{
  "status": "healthy",
  "model_loaded": true,
  "timestamp": "2026-10-04T12:00:00Z"
}
```

**Status codes:**
- 200 - сервис здоров
- 503 - модель не загружена

### 2. GET /v1/model-info
**Назначение:** Информация о загруженной модели

**Response:**
```json
{
  "model_version": "v1.0.0",
  "target": "direction",
  "lookback_window": 20,
  "feature_count": 33,
  "training_date": "2026-10-04",
  "supported_securities": ["SBER"]
}
```

**Status codes:**
- 200 - информация возвращена
- 503 - модель не загружена

### 3. POST /v1/predict/direction
**Назначение:** Прогноз направления движения цены на следующий торговый день

**Request:**
```json
{
  "security": "SBER",
  "data": [
    {
      "date": "2026-10-01",
      "open": 250.0,
      "high": 255.0,
      "low": 248.0,
      "close": 252.0,
      "volume": 1000000,
      "value": 252000000
    },
    // ... минимум 21 наблюдение (последние 20 используются для прогноза)
  ]
}
```

**Response:**
```json
{
  "prediction": 1,
  "probability": 0.67,
  "model_version": "v1.0.0",
  "target_date": "2026-10-05",
  "confidence": "medium"
}
```

**Поля:**
- `prediction`: 1 (вверх) или 0 (вниз/без изменения)
- `probability`: вероятность класса 1
- `target_date`: дата прогнозируемого торгового дня
- `confidence`: low (<0.55), medium (0.55-0.65), high (>0.65)

**Status codes:**
- 200 - успешный прогноз
- 400 - недостаточно данных (<21 наблюдения)
- 422 - невалидный формат данных
- 503 - модель не загружена

## Риски и открытые вопросы

### Риски

1. **Низкая предсказательная сила**
   - Финансовые рынки сильно зашумлены
   - Исторические паттерны могут не повторяться
   - Модель может быть не лучше random guessing

2. **Data leakage**
   - Сложно гарантировать отсутствие утечки в технических индикаторах
   - Нужно тщательное ревью каждого признака

3. **Overfitting**
   - LSTM склонна к переобучению на временных рядах
   - Нужны strong regularization и early stopping

4. **Concept drift**
   - Рыночные условия меняются (кризисы, новые регуляции)
   - Модель, обученная на исторических данных, может стать бесполезной
   - Нужен план переобучения

5. **Инфраструктурные риски**
   - MOEX API может быть недоступен
   - Задержки данных могут сделать прогноз бесполезным
   - Нужен мониторинг доступности данных

### Открытые вопросы

1. **Выбор lookback window**
   - Почему 20 дней? Можно ли улучшить с 10, 30, 60?
   - Нужно ли делать lookback настраиваемым параметром?

2. **Баланс классов**
   - Каков баланс классов в target_direction?
   - Если дисбаланс > 60/40, нужно ли использовать class weights?

3. **Метрики успеха**
   - Accuracy - достаточно ли?
   - Нужно ли оптимизировать precision/recall?
   - Какой порог вероятности использовать для классификации?

4. **Расширение на другие тикеры**
   - Обучать отдельную модель на каждый тикер?
   - Или использовать тикер как признак в одной модели?
   - Нужно ли переобучать для каждого тикера?

5. **Обновление модели**
   - Как часто переобучать? (ежедневно, еженедельно, ежемесячно)
   - Сколько данных использовать? (все истории, скользящее окно)
   - Как оценивать когда модель устарела?

6. **Альтернативные архитектуры**
   - Стоит ли попробовать Transformer/Attention?
   - Стоит ли добавить ensemble моделей?
   - Стоит ли использовать GRU вместо LSTM?

7. **Внешние данные**
   - Улучшит ли качество добавление макроэкономических данных?
   - Стоит ли добавлять sentiment analysis новостей?
   - Стоит ли добавлять данные по другим рынкам (индексы, валюты)?

8. **Production considerations**
   - Как обрабатывать пропуски в данных MOEX?
   - Что делать если торги не были в предыдущий день?
   - Как обрабатывать сплит акций, дивиденды?
